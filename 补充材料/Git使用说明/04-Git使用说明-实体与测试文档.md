## 四、如何导出自己的提交记录（在项目目录下打开 Git Bash 执行）

```bash
# 1. 查看本人所有提交（哈希 + 日期 + 说明）
git log --author="你的姓名或邮箱" --pretty=format:"%h %ad %s" --date=short

# 2. 查看本人每次提交改动的文件与增删行数
git log --author="你的姓名或邮箱" --stat

# 3. 全组提交次数与每个人的贡献统计
git shortlog -sn --all
```

## 五、本人参与发现的缺陷（测试记录）

| # | 缺陷现象 | 定位与结论 | 处理 |
| --- | --- | --- | --- |
| 1 | 客户端 `readObject` 一直阻塞、程序假死 | 两端都先创建输入流等待对方流头，形成死锁 | 建立输出流后立即 `flush()` |
| 2 | 已认领记录被第二个认领人覆盖 | `claim()` 未校验状态 | 状态为 CLAIMED 时拒绝并返回提示，方法加 `synchronized` |
| 3 | 控制台正常、重定向到文件后中文乱码 | Windows 下 JVM 按 GBK 输出 | 运行参数加 `-Dstdout.encoding=UTF-8` |
| 4 | 统计需要多次全表查询 | 每个维度各查一次 | 改为一次遍历，并补充已认领率指标 |
| 5 | 列表中每条记录都带一段较长的文字描述，显示占两行、信息密度低 | 经小组讨论，描述字段的实际使用频率很低 | 取消物品描述字段，列表与详情改为单行展示 |

## 六、与队友代码的配合

- 实体类字段的增删会同时影响序列化与快照文件，改动前与林明智确认；`serialVersionUID` 固定为 `1L`，避免反序列化失败。
- 报告中的代码片段与截图随代码修订同步更新，保证"报告与程序行为一致"。
