## 一、题目

**基于 C/S 架构的校园失物招领系统的设计与实现**

系统参照教材最后一章《知识领域9 综合实训——基于 C/S 架构的餐饮管理系统的设计与实现》仿写，题目自拟，
采用 TCP Socket + Java 对象序列化的自定义通信协议，客户端为 CMD 菜单交互程序，服务端为多线程 Socket 服务器，
数据持久化采用「内存集合 + 对象序列化快照文件」方案，无需安装任何数据库即可运行。

业务主线：失主登记寻物信息 / 拾主登记招领信息 → 条件查询 → 现场核验 → 办理认领 → 删除与统计。

## 二、技术点（从 7 个中选用 5 个）

| # | 技术点 | 用在哪里 | 关键类 / 方法 |
| --- | --- | --- | --- |
| 1 | 集合 | 内存仓库、请求参数、统计结果 | `ConcurrentHashMap`、`ArrayList`、`LinkedHashMap`、`Comparator` |
| 2 | 反射 | 命令分发：按注解自动路由网络命令 | `@RemoteCommand`、`getDeclaredMethods()`、`Method.invoke()` |
| 3 | 序列化 | 对象流传输 + `.dat` 快照持久化，一技两用 | `Serializable`、`ObjectOutputStream`、`ObjectInputStream` |
| 4 | 网络编程 | 客户端与服务端的 TCP 通信 | `ServerSocket`、`Socket` |
| 5 | 多线程 | 线程池并发处理客户端、定时线程自动保存快照 | `Executors.newFixedThreadPool`、`ScheduledExecutorService`、`CountDownLatch` |

说明：
- **泛型**在全项目中大量使用（`Map<Long, LostItem>`、`List<LostItem>` 等），但作为基础语法未单列为技术点，技术点口径严格控制在 5 项，符合「选用 3-5 个」的要求。
- **数据库编程**未选用，改用内存集合加序列化快照的轻量持久化方案，开箱即用。
- 常用类方面用到 `String`、`Date`（含 `DateTimeFormatter`）与 `Math`。
- 未使用 SSH、SpringBoot 等任何框架，仅依赖 JDK 标准库。

## 三、主要功能模块

| 包 | 作用 |
| --- | --- |
| `model` | 失物记录实体与枚举：`LostItem`、`ItemType`（LOST/FOUND）、`ItemStatus`（OPEN/CLAIMED） |
| `protocol` | 通信协议对象：`Request`（命令 + 参数表）、`Response`（消息 + 记录列表 + 统计表） |
| `repository` | 数据仓库：`ItemRepository` / `InMemoryItemRepository`（ConcurrentHashMap）、`SnapshotStore` / `FileSnapshotStore`（序列化快照） |
| `service` | 业务逻辑：`LostFoundService`（8 个业务方法）、`SeedDataInitializer`（首次运行的初始数据） |
| `command` | 命令分发：`RemoteCommand` 注解 + `CommandDispatcher`（反射） |
| `server` | 服务端：`LostFoundServer`（端口监听、线程池、定时保存、命令审计日志）、`ServerMain` |
| `client` | 客户端：`LostFoundClient`（Socket 短连接收发）、`ClientMain`（CMD 菜单） |

功能清单（客户端菜单）：

1. 发布寻物 / 招领信息，自动分配编号
2. 查看全部记录（按编号排序）
3. 条件查询（关键词 + 类型 + 认领状态三条件任意组合）
4. 查看详细信息（含认领人、认领时间）
5. 办理认领（拒绝重复认领）
6. 按编号删除记录
7. 统计：记录总数、寻物/招领数量、待认领/已认领数量、已认领率、待领取招领物数量
8. 查看帮助
9. 数据持久化：变更后立即保存 + 每 45 秒自动快照，重启自动恢复
10. 初始数据：首次运行自动写入 5 条校园失物招领信息（身份证、饭卡、书包、保温水杯、蓝牙耳机），启动即可查看与统计
